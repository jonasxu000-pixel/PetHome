# PetHome

按 06、07 号方案实现的一天版原型：建档、照片形象、短视频抽帧识别、触摸反馈、单日记录。原始方案保留在上级 `宠物/宠物` 目录。

## 本地运行

需要 Node.js 24（内置 TypeScript 测试运行器）。在本目录运行：

```powershell
npm ci
Copy-Item .env.example .env.local
# 在 .env.local 填写自己的模型密钥，不要发到聊天或提交 Git。
npm run dev
```

访问 http://localhost:3000 。同一局域网的手机可使用本机局域网 IP 和 3000 端口；是否可达还取决于网络及防火墙。公开部署前需另行配置部署平台的服务端环境变量。

## 使用

1. 创建一个宠物档案，可附 JPG/PNG 等浏览器能解码的照片（原图不超过 8MB）。
2. 在首页选择不超过 30 秒、32MB 的短视频。优先使用 H.264 MP4。
3. 开始分析。每 4 秒截取一帧，通过服务端调用视觉模型；原视频留在设备，抽取的图像会发送给所配置的模型供应商。
4. 查看行为状态，点击头部、鼻尖或横向抚摸照片。互动只作用于虚拟形象。
5. 打开今日记录。档案、照片、识别结果保存在当前浏览器 IndexedDB，不会跨设备同步。清理浏览器站点数据会删除这些内容。

照片动作采用 CSS；性格只保存档案，本版没有性格差异反馈。单帧推断不能证明持续行为，不作健康或情绪判断。

## 模型配置

`.env.local` 仅支持三个服务端变量：`AI_PROVIDER`（`gemini` 或 `zhipu`）、`GEMINI_API_KEY`、`ZHIPU_API_KEY`。主供应商失败且另一方配置了密钥时，会尝试备用供应商。密钥不可加 `NEXT_PUBLIC_` 前缀。

当前适配 Gemini `gemini-3.7-flash` 和智谱 `glm-4.6v-flash`，使用官方 REST 接口。未配置密钥时明确返回 `AI_NOT_CONFIGURED`，不生成识别成功结果。模型可用性与识别效果须用用户自己的配置和宠物素材验收。服务端内存限流和缓存仅在当前进程内有效。

## 检查

```powershell
npm test
npm run typecheck
npm run build
npm start
```

使用构建或生产模式前先停止开发服务，避免同时写 `.next`。`/api/health` 可检查模型是否已配置，不会返回密钥。

浏览器自动化、模拟模型响应和合成视频只验证程序链路；它们不代表真实识别效果、iOS/Android 真机或公网验收。
